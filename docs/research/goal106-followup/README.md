# GOAL 106 후속 — 독립 절단 검출 시도 (2026-08-06)

## 배경

GOAL 106 (g-51) 절단 sweep 은 `coordinator-final-report.md` 에서 "절단 0건 /
교정 불필요" 로 닫혔다. 그러나 그 결론은 **검출기 부재에 기반**한다:

- `scan-shard-c.py:714` `clear = disposition == "CLEAR_TRUNCATION"` 인데
  `disposition` 할당 9곳(`:764,777,781,789,800,812,823,835,839`) 어디에도
  `CLEAR_TRUNCATION` 이 없다 → 게이트 6개가 전부 상수 False.
- `omitted_tail` 은 `:759` 에서 `""` 초기화 후 재할당 없음 → 원장 17,743행
  전부 빈 문자열.

이 문서는 그 위에서 **기존 판정을 신뢰하지 않고** 절단을 독립적으로 찾아본
결과다. 데이터·기존 산출물은 읽기만 했다 (변경 0).

## 방법 C — 커버리지 갭

착상: PDF 페이지에서 **어느 데이터 주소에도 덮이지 않은 구간(갭)** 을 찾는다.
꼬리가 "다음 유닛" 이면 그 유닛이 다른 주소로 매칭되므로 갭이 아니다 —
plan.md 게이트 5(boundary proof)가 마커 사전 없이 자연히 충족된다.

`scan-shard-c.py` 를 import 해 `geometry_pages()` 로 968개 북페이지 스트림을
재구성하고, 4개 샤드 원장의 `pdf_visual` 을 페이지에 배치해 커버리지 맵을 만든다.

### 거짓 양성 4종 — 재개 시 반드시 피할 것

**(1) `tier=anchored` 행의 `pdf_visual` 은 매칭 구간이 아니다.**
`REVIEW_DIVERGENCE/anchored` 는 앵커로 페이지만 국소화한 근사 구간이라 저장값과
정렬되지 않는다. 커버리지로 쓰면 실제보다 짧게 잡혀 가짜 갭이 생긴다.

```
easter.json#/weeks/1/TUE/vespers/intercessions/2
  저장값(209자) 끝 : …нэмэгдүүлнэ үү.     ← 온전함
  pdf_visual(226자): …нэмэг               ← 단어 중간에서 끊긴 근사 구간
```

→ 커버리지로 인정할 행은 `MATCH_*` 이면서 정규화 후 `data == pdf_visual` 인 것뿐.

**(2) `text.find(vis)` 단순 배정은 반복 텍스트에서 실패한다.**
첫 출현만 돌려주므로 짧고 반복적인 값이 앞 행 안의 같은 문자열에 배정되고,
자기 자리가 비어 가짜 갭이 된다.

```
week-1.json#/days/SAT/lauds/intercessions
  [10] "өргөнө. - Бүх үйлсээрээ дамжуулан бид Танд магтаалыг"
  [11] "өргөнө."          ← [10] 안의 "өргөнө." 에 배정됨 → [11] 자리가 갭으로 오인
```

→ 한 페이지 안에서 데이터 순서와 페이지 위치가 단조 증가하도록 커서 제약을
건다 (`text.find(vis, cursor)`). v3 에서 4건 → 2건으로 감소.

**(3) 페이지 경계를 넘는 유닛.**
`week-3.json#/days/SAT/vespers/intercessions` 의 `[18]="хамт"` 는 p.312,
`[19]="байж,"` 는 **p.311** 에 매칭된다. 페이지별로 독립 분석하면 [19]가
빠져 가짜 갭이 된다.

**(4) 같은 객체의 다른 필드가 이미 담고 있는 경우.**
```
advent.json#/weeks/1/SUN/firstVespers/responsory
  versicle     : "Аяа Эзэн минь, Таны үйлсийг тунгаан бодоод"        ← 의도된 선창
  fullResponse : "…тунгаан бодоод бидний зүрх сэтгэл гайхамшгаар дүүрдэг."  ← 갭 텍스트가 여기 있음
```
→ 갭 텍스트가 **형제 필드**에 있는지 확인해야 한다. 주소 인접성만으로 부족.

## 2차 시도 (v4/v5) — 커버리지 회수와 그 한계

§커버리지 한계의 8.8% 를 끌어올리려 두 단계를 더 밟았다.

**v4 — 연속 스트림 + 저장값 재매칭.** 968 북페이지를 읽기 순서대로 이어붙인
단일 스트림(823,613자)을 만들고, 기존 `pdf_visual` 을 믿지 않고 **저장값
자체**를 3티어로 재검색했다.

| | v3 | v4 |
|---|---:|---:|
| 행 회수율 | 3,480 (19.7%) | **17,458 (98.7%)** |

거짓 양성 (1) anchored 미정렬과 (3) 페이지 경계가 구조적으로 사라진다.

**v5 — 블록 단위 통째 매칭.** v4 후보 153건을 샘플링하니 5/5 가 여전히 거짓
양성이었다. 원인은 (2) 오배정의 잔재 — 짧은 행을 개별로 찾으면 같은 문자열이
여러 번 나오는 시편에서 엉뚱한 위치에 배정된다 (`Psalm 115` 의
`Тусламж ба бамбай нь Тэр юм.` 은 한 시편에 두 번 등장). 그래서 같은 부모
배열의 형제 값을 **순서대로 이어붙여 한 덩어리로** 찾고, 덩어리가 유일하게
매칭될 때만 각 형제 위치를 배정했다.

| v5 결과 | |
|---|---:|
| 그룹 회수 | 7,572 / 12,327 (61.4%) |
| **덩어리 중복(모호)** | **4,422** |
| 스트림 커버리지 | 50.8% |
| 인접+미종결 갭 → 고유 | 258 → 195 |

**새 병목: 덩어리 중복 4,422.** 시편이 책의 여러 곳에 반복 인쇄되므로(4주
시편집 + commons) 같은 덩어리가 스트림에 여러 번 나타나 위치를 확정할 수 없다.
오배정을 없앤 대가로 회수율이 98.7% → 61.4% 로 떨어진다. 이 트레이드오프가
커버리지 갭 접근의 구조적 상한이다.

v5 잔여 195건도 상위 확인 결과 전부 구조적 노이즈였다 — 다음 찬미가 번호
(`78. Сонсооч`), 별도 필드로 저장되는 attribution (`(Арнобиус).`), 글리프
분리된 섹션 제목 (`ншлага` = `Уншлага`).

**결론: 절단은 v1~v5 어디서도 나오지 않았다.** 커버리지 갭 접근은 이 데이터의
구조(시편 반복 인쇄 + 데이터가 PDF 의 일부만 수록)에서 신호 대 잡음비가
근본적으로 나쁘다.

## 재개 시 필요한 것

1. **anchored/unproven 행의 재매칭** — 5,416행이 커버리지 밖이다. 이들을
   정확한 구간으로 국소화하지 않으면 판정 가능 비율이 오르지 않는다.
2. **페이지 경계 병합** — 인접 북페이지를 이어 붙인 스트림에서 분석해야
   거짓 양성 (3)이 사라진다.
3. **형제 필드 인지** — 갭 텍스트가 같은 부모 객체의 다른 필드에 있는지
   확인하는 단계 (거짓 양성 (4)).
4. 그 위에서야 `scan-shard-c.py` 에 `truncation_signature()` 주입이 의미를
   갖는다. 주입 지점은 `make_row()` 의 `:788` `elif match:` 직전이며,
   `find_match_on_pages()` `:491-499` 의 반환 dict 에 `visual_start`/
   `visual_end` 를 추가하는 것이 선행 조건이다.
