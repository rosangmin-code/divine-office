# 저녁 시간대 우선순위 — 전례일 순위표 적용 (FR-176) + 주님의 축일 제2저녁기도 (FR-177)

- **발견/작업**: 2026-09-17, `docs/bug-reports/2026-09-17-holy-saturday-evening-cards.md` §6 "미수정으로 남긴 것" 후속
- **사용자 판단**: 몽골어 책은 전례일 순위표를 인쇄하지 않는다. 보편 순위표를 적용하기로 결정 (2026-09-17)
- **영향**: FR-176 = 11년에 2회(1월 1일) + 2년에 1회(토요일 대축일/주님의 축일). FR-177 = **매년 4일**

---

## 1. 배경 — 저녁은 하루에 하나뿐이다

오늘의 제2저녁기도와 내일의 제1저녁기도가 같은 저녁을 놓고 겨룬다. 보편규범 61항과
전례일 순위표가 승자를 정하는데, **몽골어 책에는 그 순위표가 인쇄돼 있지 않다**
(책 p.18-20 의 «Залбиралт цагийг ёслон тэмдэглэх заавар» 는 각 시간경의 구성만
나열한다). 그래서 이 판정은 코드가 스스로 정할 수 없고, 사용자 결정이 필요했다.

앱은 이미 순위표를 부분 적용하고 있었다 — #240(연중 주일 vs 월요일 대축일),
#245(대림→성탄 경계), FR-173(성탄 vs 성가정), FR-175(성토요일·토요일 성탄).
이번에 남아 있던 두 구멍을 메운다.

## 2. FR-176 (a) — 1월 1일이 토요일인 해의 저녁

### 증상 — 앱이 두 답을 동시에 냈다

```
2028-01-01 (토) 하느님의 어머니 성모 마리아
  카드           = firstVespers, firstCompline, lauds       ← 저녁 없음 = "내일 공현으로 가라"
  /pray/2028-01-02/firstVespers = 공현 제1저녁기도 «Одыг хараад мэргэд…»
  /pray/2028-01-01/vespers      = 1월 1일 제2저녁기도 «Аяа Христ минь…»   ← 카드와 불일치
```

### 인쇄면 — 두 기도문 다 책에 있다

물리 페이지 305 (책 608/609), 200dpi 렌더 확인:

- 좌(책 p.608): «**2 дугаар Оройн даатгал залбирал**» — 1월 1일 제2저녁기도
- 우(책 p.609): «1 дүгээр сарын 6 эсвэл 1 дүгээр сарын 2-оос 8-ны хоорондох Ням гараг /
  **ЭЗЭНИЙ ИЛРЭХҮЙ** / Их баяр» → «МАРИАГИЙН МАГТААЛ / Шад дуулал **Одыг хараад
  мэргэд…**» → «Урих дуудлага» → «Өглөөний даатгал залбирал»

공현 구역 맨 앞의 Magnificat 후렴은 표제(«1 дүгээр Оройн даатгал залбирал»)가 없을
뿐 **위치상 전야 기도**다 — 초대송·아침기도보다 앞에 있다. 데이터도 FR-171 규약대로
`christmas.json weeks.epiphany.SUN.vespers`(p.609) = 제1저녁기도,
`.vespers2`(p.610, «Гурван ариун нууц…») = 제2저녁기도로 들어와 있다.

> 인계 문서 `docs/handoff-2026-09-17-review-session.md` §3 에 "책이 공현 EP I 을
> 별도 블록으로 인쇄하지 않음 → 데이터 설계 결정 필요" 라고 적혀 있던 것은
> **오기**다. 데이터는 있었고, 평범한 해(2026-01-03 등)에는 이미 정상 동작했다.

### 원인

`getSeasonFirstVespers` 가 `weeks[specialKey].SUN.firstVespers` 키만 찾는다.
`epiphany` 버킷에는 그 키가 없어 null → 전야 승격 Path 2 가 실패 → 1월 1일 자신의
성인 고유부가 남았다. 평범한 해에는 토요일에 고유부가 없어 «토→주일» 분기가
`SUN.vespers` 를 그대로 집어 우연히 맞았다.

### 수정

`getSeasonFirstVespers` 에 **`vespers2` 를 가진 특수키 셀의 `vespers` 는 제1저녁기도**
라는 폴백을 추가한다(FR-171 규약). `vespers2` 없는 셀(`easterSunday`, `jan1`,
`octave`, `epiphanyWeek`)은 단일 «Оройн даатгал залбирал» = 그날 자신의 저녁기도라
제외된다. 실제로 이 폴백이 걸리는 특수키는 `epiphany` 하나다(`dec25` 는
`resolveSpecialKey` 가 null 을 주고 성인 고유부 경로가 앞선다).

추가로, 승격이 일어난 저녁에는 **오늘의 성인 고유부를 얹지 않는다**. 그러지 않으면
공현 제1저녁기도 위에 1월 1일 후렴이 덮인다. 대상은 `vespers2` 를 가진 엔트리로
한정 — All Souls(11-02)는 단일 `vespers` + FR-160-B-7 이 토요일 전야에 의도적으로
남겨 둔 substitute 지시가 있어 게이트 밖이다.

## 3. FR-176 (b) — 토요일에 오는 대축일 / 주님의 축일

### 증상

```
2026-08-15 (토) 성모 승천
  카드           = firstVespers, firstCompline, lauds      ← 저녁 없음
  본문 저녁       = 다음 연중 20주일의 제1저녁기도로 승격
  → 책 p.834 에 인쇄된 승천 제2저녁기도에 도달할 길이 없음
```

순위표상 대축일(I.3)과 주님의 축일(II.5)은 연중·성탄 주일(II.6)을 이긴다.
사순·대림·부활 주일(I.2)은 반대로 대축일을 이기므로 건드리지 않는다.

### 수정

`keepsOwnEveningPrayerII` 에 규칙 (c) 추가:

```
오늘이 주일이 아니고
  && 오늘 성인 고유부에 vespers2 가 있고        ← "책이 제2저녁기도를 인쇄한 날"
  && 내일이 평범한 주일(romcalType === 'SUNDAY')이고
  && 내일이 대림·사순·부활 주일이 아니면
→ 오늘 제2저녁기도를 지킨다
```

`vespers2` 를 게이트로 쓴 이유: 그 집합이 정확히 대축일 8개 + 주님의 축일 4개이고,
성인 축일(II.7 — 주일을 이기지 못한다)은 자동으로 빠진다. `romcalType === 'SUNDAY'`
는 "평범한 주일" 을 뜻한다 — 공현·성가정 같은 상위 축제가 주일을 대체한 경우 romcal
이 그 축제의 타입을 내므로 규칙이 발동하지 않는다(공현은 이기는 게 맞다, §2).
`dayOfWeek !== 'SUN'` 도 필수 — romcal 은 **모든 주일**을 `SOLEMNITY` 로 표시한다.

평범한 «토→주일» 분기에도 같은 게이트를 걸어야 한다. FR-156 분기만 막으면 본문이
여전히 주일로 승격돼, 승천의 후렴이 주일의 시편 위에 얹히는 잡종이 된다.

## 4. FR-177 — 주님의 축일 당일 저녁기도가 **제1저녁기도**였다 (매년 4일)

### 증상

```
2026-02-02 (월) 주님 봉헌 축일   → 렌더: «Хөгшин хүн бяцхан хүүг…»  = 제1저녁기도 ❌
                                   책 제2저녁기도: «Өнөөдөр төгс жаргалт…» (p.822)
2026-08-06 거룩한 변모 · 2026-09-14 십자가 현양 · 2026-11-09 라테라노 — 전부 동일
```

대축일은 정상(`day.rank === 'SOLEMNITY'` 게이트), **축일만** 빠져 있었다.
FR-171(주일 제2저녁기도)과 똑같은 결함 형태다.

### 인쇄면 근거

책 p.821 (물리 411) 적색 규정:

> «Хэрэв энэ баяр **Ням гарагт таарвал** 1 дүгээр Оройн даатгал залбирал уншина.»
> (이 축일이 **주일에 걸리면** 제1저녁기도를 읽는다.)

즉 그 셀은 제1저녁기도이고, 쓰임이 주일 occurrence 로 한정된다. p.831(변모)·
p.835(십자가 현양)에 같은 주석이 있고, p.840(라테라노)은 표제만 있고 주석이 없다 —
데이터의 `conditionalRubrics` 가 이 per-feast 차이를 그대로 담고 있다(11-09 만 없음).

### 수정

`hour === 'vespers' && day.rank === 'SOLEMNITY' && sanctoral?.vespers2` 의 rank 조건에
`|| day.rank === 'FEAST'` 를 더한다. `vespers2` 보유 엔트리는 대축일 8 + 주님의 축일 4
뿐이고 기념일·성인 축일은 하나도 없으므로 rank 조건은 방어용이다.

## 5. 검증 — 2026-2035 전일자 × 시간경 지문 스윕

`getHoursSummary` + `assembleHour` 5 시간경을 3,653일 전부 돌려 수정 전후 diff
(섹션 타입·후렴·독서 ref·본문·page·시편 참조·`effectiveLiturgicalDay`):

| 범주 | 줄 |
|---|---|
| FR-177 주님의 축일 당일 제2저녁기도 (02-02·08-06·09-14·11-09 × 10년, 토요일 해는 카드도) | 44 |
| FR-176(b) 토요일 대축일/주님의 축일이 자기 제2저녁기도 유지 (카드+본문) | 10 |
| FR-176(c) 승격된 저녁에서 오늘 성인 고유부 제거 (03-19·03-25·12-08·03-17) | 6 |
| FR-176(a) 공현 전야 — 2028·2033 은 본문 교체, 나머지 8건은 `effectiveLiturgicalDay` 선언만 | 10 |
| **예상 밖 범주** | **0** |

`effectiveLiturgicalDay` 를 제외하면 내용이 바뀐 줄은 63 — 평범한 해의 공현 전야
8건은 본문 글자 단위로 동일하고 승격 정체성만 새로 선언한다.

핵심 동치 확인:

```
2028-01-01/vespers  ≡  2026-01-03/vespers   (후렴·본기도 동일 — 평범한 해의 공현 전야)
2026-08-15/vespers  ≡  2028-08-15/vespers   (토요일 승천 ≡ 화요일 승천, 본기도 x.834)
2030-02-02/vespers  =  feasts['02-02'].vespers2
```

스위트: vitest 2,105 통과, Playwright 980 통과 / 34 skip / 0 실패, `verify:all`
14 PASS, tsc 0, ESLint 0 error. 시각 확인 390×900 — 2026-08-15 카드 5장,
2028-01-01 본문 렌더 정상, console/pageerror 0.

## 6. 남긴 것

| 항목 | 이유 |
|---|---|
| **주님의 축일의 `firstVespers` 카드가 비주일 occurrence 에도 뜬다** | 책 p.821/831/835 는 제1저녁기도를 **주일에 걸릴 때만** 읽으라고 한다. 지금은 `hasFirstVespersAndCompline` 이 `sanctoral.firstVespers` 존재만 보고 요일을 보지 않아, 2026-02-02(월) 같은 날에도 카드가 뜨고 `/firstVespers` 가 200 을 준다. 라테라노(11-09)에는 그 주석이 없어 축일별로 다르다 — 카드 모델과 라우트 적격성을 함께 건드려야 하는 별건 |
